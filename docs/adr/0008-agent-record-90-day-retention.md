# ADR-0008: 에이전트 기록 90일 자동 보존

- 상태: Accepted
- 날짜: 2026-07-28

## Context

에이전트 기록은 최근 업무 흐름과 회고에 유용하지만 무기한 보존할 필요는 없습니다. 기본 저장 필드는 최소 메타데이터이지만, 사용자가 프로젝트 경로나 응답 일부 저장을 opt-in하면 개인정보 민감도가 높아집니다.

후보는 사용자 삭제 전까지 보존, 30일 자동 보존, 90일 자동 보존이었습니다.

## Decision

- AgentRun과 하위 AgentEvent의 기본 보존 기간은 90일입니다.
- 만료 기준은 `AgentRun.receivedAt`입니다.
- 90일이 지난 AgentRun을 삭제할 때 연결된 AgentEvent를 cascade 삭제합니다.
- 정리는 앱 시작 시와 새 에이전트 이벤트 저장 후 실행합니다.
- 별도 백그라운드 스케줄러는 두지 않습니다.
- 앱이 장기간 실행되지 않으면 다음 실행 시 만료 데이터를 정리합니다.
- Task, Article, BriefingRun과 앱 설정에는 이 보존 정책을 적용하지 않습니다.

## Consequences

### Positive

- 월간·분기 단위 회고에 활용할 수 있습니다.
- 민감할 수 있는 에이전트 메타데이터를 무기한 축적하지 않습니다.
- 별도 스케줄러 없이 기존 앱 수명 주기에 정리를 결합할 수 있습니다.

### Negative

- 90일보다 오래된 에이전트 기록은 복구할 수 없습니다.
- 앱이 실행되지 않는 동안에는 실제 삭제 시점이 90일을 넘길 수 있습니다.
- 장기 통계나 연간 회고에는 별도 집계 데이터가 필요합니다.

## Alternatives

- 사용자 삭제 전까지 보존: 사용성은 높지만 개인정보 최소화 원칙과 데이터 증가 때문에 제외했습니다.
- 30일 보존: 개인정보 측면에서는 더 보수적이지만 분기 회고 활용이 어려워 제외했습니다.
- 백그라운드 정리 작업: 정확한 삭제 시각을 제공하지만 MVP의 수동·로컬 실행 모델과 맞지 않아 제외했습니다.
