# ADR-0003: 수동 브리핑과 무재시도 정책

- 상태: Accepted
- 날짜: 2026-07-28
- 개정: 2026-07-29

## Context

정시 브리핑과 백그라운드 피드 수집은 macOS 앱 수명 주기, 절전 상태, 재시도와 스케줄 관리가 필요합니다. MVP의 핵심은 사용자가 메뉴 막대에서 빠르게 하루 정보를 확인하는 것이며, 자동화보다 예측 가능한 동작과 작은 구현 범위가 우선입니다.

## Decision

- 브리핑은 사용자가 메뉴 막대의 "아티클 추천받기" 버튼을 누를 때만 실행합니다.
- 한 번의 실행에서 피드 조회, 메타데이터 파싱과 아티클 선정을 각각 한 번 수행합니다.
- 자동 재시도와 별도의 재시도 버튼을 제공하지 않습니다.
- 다음 버튼 동작은 이전 실패의 재시도가 아니라 새로운 브리핑 실행입니다.
- 어제 한 일과 오늘 할 일 요약은 로컬 데이터에서 결정적으로 생성합니다.
- 오늘의 아티클 영역에는 추천 아티클만 표시하고, 어제 한 일과 오늘 할
  일은 각각의 독립된 영역에 표시합니다.
- 피드 조회가 실패해도 독립된 로컬 할 일 영역은 유지합니다.

## Consequences

### Positive

- 피드 네트워크 사용 시점을 사용자가 통제합니다.
- 스케줄러, 백오프, 중복 작업과 절전 복구 로직이 필요 없습니다.
- 실패 동작이 단순하고 테스트하기 쉽습니다.

### Negative

- 사용자가 버튼을 누르기 전에는 새 브리핑이 준비되지 않습니다.
- 일시적인 네트워크 오류도 해당 실행에서는 복구하지 않습니다.
- 자동 아침 브리핑이라는 장기 제품 경험은 MVP 이후에 구현해야 합니다.

## Alternatives

- 지정 시각 자동 실행: 앱 수명 주기와 절전 복구 복잡성 때문에 2단계로 미뤘습니다.
- 주기적 백그라운드 수집: 최신성 대비 구현·배터리 비용이 커 제외했습니다.
- 지수 백오프 재시도: 사용자 요청당 한 번이라는 예측 가능성을 우선해 제외했습니다.
