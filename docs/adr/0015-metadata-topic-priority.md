# ADR-0015: 메타데이터 기반 아티클 주제 우선순위

- 상태: Accepted
- 날짜: 2026-07-30

## Context

GeekNews와 Korean FE Article은 개별 글을 제공하지만 기술 범위가 넓습니다.
최신성이나 소스 가중치만으로 선정하면 사용자가 가장 선호하는 AI와
프론트엔드보다 인프라·데이터 또는 일반 개발 글이 먼저 추천될 수 있습니다.

모래는 ADR-0010에 따라 피드 본문과 원문을 처리하지 않으며 AI API도
사용하지 않습니다. 따라서 주제 우선순위는 저장 중인 제목 메타데이터
범위 안에서 결정해야 합니다.

## Decision

- 제목의 한국어·영어 토큰, 구문과 제한된 한글 fragment를 사용해 다음
  우선순위 점수를 부여합니다.
  - AI·프론트엔드: 120
  - 협업: 45
  - 인프라·데이터: 20
  - 기타: 0
- 둘 이상의 주제와 일치하면 가장 높은 점수 하나만 적용합니다.
- `AI로`, `React를`처럼 영문 기술명 뒤에 한글 조사가 붙어도 영문
  토큰을 별도로 추출합니다.
- 주제 점수는 기존 최신성, 사용자 관심사, 소스 가중치, 읽음과 최근 추천
  점수에 더합니다.
- 최근 90일 추천 감점은 유지해 같은 상위 주제 글만 반복되는 것을
  완화합니다.
- 키워드 집합은 코드에 고정하며 MVP 설정 UI에는 노출하지 않습니다.
- 주제 판별은 `ArticleTopicClassifier`, 전체 후보 점수 계산과 선택은
  `ArticleSelector`가 담당합니다.

## Consequences

### Positive

- 별도 API 비용이나 원문 수집 없이 개인 선호 순서를 강하게 반영합니다.
- 결과가 결정론적이므로 fixture와 고정 Clock으로 회귀 검증할 수 있습니다.
- 제목에 여러 주제가 있어도 AI·프론트엔드가 가장 높은 우선순위를
  갖습니다.

### Negative

- 제목에 주제가 명시되지 않으면 실제로 관련된 글도 기타로 분류될 수
  있습니다.
- `team`, `data`, `web`처럼 넓은 키워드는 문맥에 따라 오분류될 수
  있습니다.
- 개인 선호가 바뀌면 코드와 문서를 수정해야 합니다.

## Alternatives

- 관심사 배열의 순서만 사용: 현재 관심사 모델은 집합 일치 비율이라
  카테고리 사이의 큰 우선순위를 표현하기 어렵습니다.
- 본문 임베딩 또는 LLM 분류: 의미 정확도는 높일 수 있지만 본문 수집,
  API 비용과 키 관리가 필요해 제외했습니다.
- 주제별 피드만 추가: 소스 수와 중복이 늘고 GeekNews 내부의 다양한
  개별 글을 활용하기 어려워 제외했습니다.
