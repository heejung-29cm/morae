# ADR-0014: 신선한 개별 아티클 중심 추천

- 상태: Accepted
- 날짜: 2026-07-30
- 대체: ADR-0013의 기본 소스 구성

## Context

Frontend Focus와 JavaScript Weekly 같은 피드는 각 호 자체를 RSS 항목으로
제공합니다. 제목과 링크만 사용하는 모래에서는 한 호 안의 개별 원문을
평가할 수 없어, 사용자가 원하는 새로운 정보와 작성자의 관점이 담긴 글
대신 뉴스레터 목차 페이지가 추천될 수 있습니다. 오래된 항목이나 게시일이
없는 항목도 높은 소스 가중치로 선택될 수 있었습니다.

오늘의 아티클 아래에 어제 한 일과 오늘 할 일을 다시 표시하고 첫 실행
질문까지 포함한 화면은 독립된 할 일 섹션과 역할이 겹쳤습니다.

## Decision

- 기본 피드는 GeekNews와 Korean FE Article 두 개만 활성화합니다.
- FE News, Frontend Focus, JavaScript Weekly와 이전 공식 문서 기본 피드는
  `default_feeds_seeded_v3` 전환에서 비활성화합니다.
- 사용자 정의 피드는 그대로 유지합니다.
- 게시일이 있는 실행 시점 기준 최근 30일의 항목만 선정 후보로 사용합니다.
  피드 서버 시계 오차를 위해 미래 게시일은 하루까지 허용합니다.
- Korean FE Article 제목의 반복 접두어 `[Korean FE Article]`은 표시 전에
  제거합니다.
- 제목, 링크, 출처와 게시일만 처리하는 ADR-0010 경계와 무재시도 정책은
  유지합니다.
- 오늘의 아티클 섹션에서는 할 일 요약과 첫 실행 최우선 할 일 질문을
  제거합니다. 아티클 추천받기 버튼은 즉시 한 번 실행하고, 할 일은 어제 완료와
  오늘 할 일 섹션에서만 표시합니다.

## Consequences

### Positive

- 뉴스레터 목차 페이지보다 하나의 주제를 다루는 커뮤니티 토픽과
  작성·번역된 프론트엔드 글을 추천합니다.
- 게시 주기가 느린 소스의 오래된 글이 가중치만으로 선택되지 않습니다.
- 아티클과 할 일 영역의 책임이 분리돼 화면이 간결해집니다.
- AI API, 본문 수집, 유료 인프라 없이 기존 개인정보 경계를 유지합니다.

### Negative

- 기본 소스가 두 개라 한 소스 장애 시 후보 다양성이 줄어듭니다.
- 30일 동안 새 글이 없으면 추천 결과가 없을 수 있습니다.
- 제목과 메타데이터만으로 글의 실제 깊이나 독창성을 완전히 평가할 수
  없습니다.

## Alternatives

- 뉴스레터 본문에서 개별 링크 추출: 더 많은 후보를 얻지만 본문을
  처리하지 않는 ADR-0010 경계를 넓혀 제외했습니다.
- AI로 본문 품질 평가: 원문 수집, API 비용과 키 관리가 필요해
  제외했습니다.
- 오래된 후보를 fallback으로 사용: 항상 결과를 낼 수 있지만 “새로운
  정보”라는 추천 목표를 약화해 제외했습니다.
