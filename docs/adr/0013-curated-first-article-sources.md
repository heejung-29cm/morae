# ADR-0013: 큐레이션 우선 아티클 소스와 선정 가중치

- 상태: Accepted
- 날짜: 2026-07-30

## Context

초기 기본 피드는 MDN, web.dev, Chrome for Developers와 React Blog처럼
신뢰할 수 있는 공식 문서·제품 블로그로 구성했습니다. 정확성은 높지만
릴리스 공지와 제품 업데이트 비중이 커서, 매일 한 개를 읽기 위한
발견형 추천으로는 범위와 관점이 단조로웠습니다.

GeekNews, FE News와 주간 프론트엔드 뉴스레터는 운영자·커뮤니티가 여러
출처에서 읽을 만한 글을 먼저 선별합니다. 다만 최신성 점수만 사용하면
항목 발행 빈도가 높은 GeekNews가 월간·주간 뉴스레터를 항상 앞설 수
있습니다. 새 기본 피드만 추가할 경우 기존 네 개 공식 피드가 브리핑의
최대 네 개 조회 슬롯을 계속 차지하는 기존 설치 문제도 있습니다.

## Decision

- 기본 피드를 다음 네 큐레이션 소스로 교체합니다.
  - GeekNews
  - FE News
  - Frontend Focus
  - JavaScript Weekly
- 피드 소스에 `selectionWeight` 0...100을 저장하고 후보 선정 점수에
  더합니다.
- 기본 가중치는 발행 빈도와 큐레이션 밀도를 고려해 GeekNews 20,
  FE News 55, Frontend Focus 45, JavaScript Weekly 45로 둡니다.
- 최신성과 최근 추천 감점은 계속 적용합니다. 새 뉴스레터 호는 한 번
  우선될 수 있고, 추천된 URL은 다음 실행에서 60점 감점을 받아 다른
  소스로 순환할 수 있습니다.
- `default_feeds_seeded_v2` marker를 사용합니다. 기존 설치에서 v2 seed를
  처음 실행할 때 기존 네 기본 피드만 비활성화하고 새 기본 피드를
  추가합니다. 사용자 정의 피드는 변경하지 않습니다.
- `isOfficial`은 해당 서비스가 직접 제공하는 공식 피드인지 계속
  나타내며, 큐레이션 선호는 별도 `selectionWeight`로 표현합니다.
- GeekNews는 개별 GeekNews 토픽 링크를 추천합니다. FE News와 주간
  뉴스레터는 해당 큐레이션 호 링크를 추천합니다.
- 피드의 description/content에서 개별 원문을 추출하지 않습니다. 제목,
  링크, 출처와 게시일만 사용하는 ADR-0010의 경계를 유지합니다.

## Consequences

### Positive

- 공식 제품 공지보다 사람이 선별한 개발·프론트엔드 읽을거리가 우선됩니다.
- 최신성, 관심사, 읽음·최근 추천과 소스 품질을 함께 조절할 수 있습니다.
- 높은 빈도의 단일 피드가 추천을 독점하지 않고 주간·월간 큐레이션과
  순환할 수 있습니다.
- 기존 사용자의 DB를 삭제하지 않고 다음 앱 실행에서 기본 소스 구성을
  전환할 수 있습니다.
- 사용자 정의 피드와 메타데이터-only 개인정보·비용 경계는 유지됩니다.

### Negative

- `selectionWeight`는 편집자의 정적 판단이므로 실제 만족도를 직접
  측정하지 않습니다.
- GeekNews 링크는 원문이 아니라 GeekNews 토픽 페이지를 엽니다.
- FE News와 주간 뉴스레터는 내부 개별 글이 아니라 한 호 전체가 추천
  단위입니다.
- 소스 품질이나 발행 패턴이 바뀌면 기본 가중치를 다시 검토해야 합니다.

## Alternatives

- 기존 공식 피드 유지: 정확하지만 사용자가 원하는 발견형 추천 성격이
  약해 제외했습니다.
- GeekNews만 사용: 간단하지만 기술 범위가 넓고 단일 소스 의존이 커
  제외했습니다.
- 뉴스레터 본문에서 개별 링크 추출: 더 세밀한 추천이 가능하지만
  content를 처리하지 않는 ADR-0010 경계를 깨므로 제외했습니다.
- AI로 본문 품질 평가: API 비용, 키 관리와 원문 수집이 필요해 MVP에서
  제외했습니다.
