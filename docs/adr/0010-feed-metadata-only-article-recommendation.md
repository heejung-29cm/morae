# ADR-0010: 피드 메타데이터만 사용하는 아티클 추천

- 상태: Accepted
- 날짜: 2026-07-29
- 대체: ADR-0007

## Context

MVP의 목적은 사용자가 최근 프론트엔드 아티클을 발견하고 원문으로 이동하게 돕는 것입니다. AI 요약을 위해서는 유료 API 키, Keychain 저장, 원문 HTML 수집, 본문 추출과 실패 처리가 추가로 필요합니다. 개인용 MVP에서는 이 비용과 복잡성이 제목과 원문 링크 제공으로 얻는 가치보다 큽니다.

## Decision

- 사용자가 "오늘 브리핑 만들기"를 누를 때만 등록된 RSS/Atom 피드를 한 번 조회합니다.
- 피드 항목에서 제목, 링크, 출처와 게시일만 처리합니다.
- 피드의 본문·요약과 아티클 원문 HTML은 가져오거나 저장하지 않습니다.
- 최근성, 제목의 관심사 일치, 공식 출처 여부와 최근 추천 여부로 아티클 한 개를 선정합니다.
- 결과에는 제목, 출처, 게시일과 원문 링크만 표시합니다.
- Anthropic API, API 키, Keychain, SwiftSoup과 외부 본문 추출 서비스를 사용하지 않습니다.
- 피드 실패 시 자동 재시도하지 않고 할 일 요약과 아티클 오류 상태를 표시합니다.

## Consequences

### Positive

- 유료 API와 비밀 키가 없어 외부 준비, 비용과 보안 범위가 줄어듭니다.
- 아티클 원문을 처리하지 않아 네트워크와 개인정보 경계가 단순해집니다.
- 구현·테스트 대상이 피드 파싱, 선정과 메타데이터 저장으로 축소됩니다.

### Negative

- 앱 안에서 아티클 핵심 내용이나 예상 읽기 시간을 확인할 수 없습니다.
- 제목만으로 관심사를 판별하므로 추천 정확도가 제한될 수 있습니다.
- 자세한 내용은 사용자가 원문 링크를 열어 확인해야 합니다.

## Alternatives

- Anthropic API 요약: 풍부한 브리핑을 제공하지만 비용, 키 관리와 실패 처리가 필요해 제외했습니다.
- 로컬 모델 요약: 외부 API 비용은 없지만 모델 배포 크기와 실행 자원 부담이 커 제외했습니다.
- 피드가 제공하는 summary 표시: 구현은 가능하지만 출처별 품질과 길이 편차가 커 MVP에서는 사용하지 않습니다.
