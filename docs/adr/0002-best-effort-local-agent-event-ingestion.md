# ADR-0002: UDS 기반 best-effort 에이전트 이벤트 수신

- 상태: Accepted
- 날짜: 2026-07-29

## Context

Codex `notify`와 Claude Code Hook은 이벤트가 발생할 때 외부 명령을 실행할 수 있습니다. MVP는 에이전트 이벤트를 외부 서버로 보내지 않으며, 앱이 실행 중일 때의 편의 알림만 필요합니다. 앱이 종료된 동안의 이벤트 복구는 MVP 완료 조건이 아닙니다.

## Decision

- `hamster-event`를 이벤트마다 실행되는 짧은 수명의 CLI로 구현합니다.
- 실행 중인 메뉴 막대 앱과 Unix Domain Socket으로 통신합니다.
- 소켓은 사용자 전용 임시 디렉터리에 만들고 부모 디렉터리 `0700`, 소켓 `0600`, peer UID 검증을 적용합니다.
- 연결 하나당 크기 제한이 있는 이벤트 하나만 전송합니다.
- 원본 입력은 760 KiB, base64 envelope JSON frame은 1 MiB로 제한합니다.
- helper process 시작 시 900ms total deadline을 설정하고 connect는 최대 250ms, write와 ACK read는 남은 시간을 공유합니다.
- 앱이 저장을 마치면 ACK를 반환합니다.
- 연결 또는 ACK가 실패해도 CLI는 재시도하거나 이벤트를 파일에 적재하지 않습니다.
- 성공, 설정 오류와 모든 전달 실패에서 stdout/stderr 출력 없이 exit code 0으로 종료합니다.
- 앱이 실행 중이지 않으면 이벤트를 폐기합니다.
- 사용자는 로그인 시 앱 자동 실행을 선택할 수 있으며 기본값은 꺼짐입니다.

## Consequences

### Positive

- 별도 데몬, 큐, 서버 없이 구현할 수 있습니다.
- 에이전트의 실행 흐름을 Hook 전달 실패 때문에 중단하지 않습니다.
- 이벤트가 디스크의 임시 큐에 원본 형태로 남지 않습니다.

### Negative

- 앱 종료, 업데이트, 크래시 중 발생한 이벤트는 복구할 수 없습니다.
- 감사 로그나 정확한 작업 이력으로 사용할 수 없습니다.
- ACK 유실 시 저장 성공 여부를 CLI가 확정할 수 없지만 재전송하지 않으므로 신뢰성보다 단순성을 선택합니다.

## Alternatives

- 로컬 파일 스풀: 내구성은 높지만 정리, 중복 처리, 원본 payload 보호가 추가로 필요해 MVP에서 제외했습니다.
- LaunchAgent 상시 수신기: 설치와 수명 주기 관리가 복잡해 제외했습니다.
- 로컬 HTTP 서버: 불필요한 포트 노출과 인증 부담 때문에 제외했습니다.
- Codex App Server: 더 풍부한 상태를 제공하지만 단순한 종료 알림 범위를 넘어가므로 후속 단계로 미뤘습니다.
