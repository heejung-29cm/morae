# Sprint 3 수동 브리핑 데모 체크리스트

> 기준일: 2026-07-30
> 범위: S3-01~S3-07

## 1. 실행 전 확인

1. Xcode에서 `Morae` 프로젝트와 `MoraeApp` scheme을 선택합니다.
2. 이전에 실행 중인 모래가 있으면 메뉴 막대에서 종료하거나 Xcode의
   Stop 버튼을 눌러 한 인스턴스만 남깁니다.
3. `Product > Run`을 실행하고 메뉴 막대의 모래 아이콘을 누릅니다.
4. 화면을 열기만 했을 때 브리핑이 자동 생성되지 않는지 확인합니다.

## 2. 첫 브리핑

1. `오늘 브리핑`을 누릅니다.
2. 별도 할 일 질문 없이 바로 피드 조회가 시작되는지 확인합니다.
3. 버튼이 `생성 중`으로 바뀌고 완료 전에는 다시 누를 수 없는지
   확인합니다.
4. 완료 후 오늘의 아티클 섹션에 다음 정보만 표시되는지 확인합니다.
   - 추천 아티클 제목, 출처, 게시일
   - `원문 열기`
5. 어제 완료와 오늘 할 일은 각각 독립된 섹션에만 표시되는지 확인합니다.
6. 아티클 카드를 눌러 기본 브라우저에서 원문이 열리는지 확인합니다.

## 3. 재실행과 실패 정책

1. 같은 날짜에 `오늘 브리핑`을 다시 누릅니다.
2. 새 브리핑이 한 번만 생성되는지 확인합니다.
3. 화면에 별도의 `재시도` 버튼이 없는지 확인합니다.
4. 일부 피드만 실패하면 성공한 피드의 추천과 부분 실패 안내가 함께
   표시됩니다.
5. 모든 피드가 실패하면 아티클 오류가 표시되고, 독립된 어제 완료·오늘
   할 일 섹션은 유지되는지 확인합니다. 같은 실행에서 자동 재시도하지
   않습니다.

실패 경계와 요청 횟수는 자체 제작 fixture를 사용하는 자동화 테스트로
재현합니다.

```sh
xcodebuild test \
  -project Morae.xcodeproj \
  -scheme MoraeApp \
  -destination 'platform=macOS' \
  -only-testing:MoraeAppTests/GenerateBriefingTests
```

## 4. 앱 재시작

1. 모래를 종료합니다.
2. Xcode에서 다시 `Product > Run`을 실행합니다.
3. 메뉴를 열었을 때 네트워크 요청이나 자동 브리핑 없이 같은 날짜의
   마지막 성공 또는 실패 결과가 복원되는지 확인합니다.
4. 복원된 아티클 카드의 원문 링크가 계속 열리는지 확인합니다.

`testManualRerunCreatesOneRunAndLatestSurvivesDatabaseReopen`은 임시 DB를
실제로 닫고 다시 열어 버튼 동작당 `briefing_runs` 한 건, 최신 실행 복원과
피드별 요청 한 번을 검증합니다.

## 5. Sprint 3 완료 기준

- 네트워크는 사용자가 브리핑 생성을 확정할 때만 시작합니다.
- 한 번의 생성 동작은 활성화된 피드를 최대 4개까지 각각 한 번만 조회합니다.
- 로컬 요약과 추천 메타데이터를 저장하고 최신 실행을 다시 표시합니다.
- 오늘의 아티클 섹션에는 아티클만 표시합니다.
- 자동 재시도와 재시도 버튼이 없습니다.
- 피드 본문·아티클 원문·AI 요약은 수집하거나 저장하지 않습니다.
